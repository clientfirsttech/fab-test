# Changelog

## 2026-11-22

- 🐛 - Data Agent Runs Are Polite To A Busy Fabric - When Fabric throttles an agent (429 `RequestBlocked`), fab-test waits the `Retry-After` it names once, and if the agent is still blocked, stops asking it for the rest of the run. Every other question says `Not asked: …` at once. Before, the provider retried every 2 s and promptfoo retried around it, up to 16 requests per question, which kept the block alive. The run then ended after 198 s with the Node command line. Now the envelope's `message` names the cause once ("3 of 7 questions could not be asked: …"), and `retry_after` (UTC) says when to come back. A run that outlives `--timeout` says how many questions came back and the last failure. A 400, 404 or other final 4xx, a DNS failure or an untrusted certificate is reported after one request, not four, as one sentence naming the host and the fix, never raw JSON. A 5xx, a timeout or a dropped connection is retried with capped, jittered backoff that honors `Retry-After`. Live progress prints why a question failed. **Behavior change**: an agent run that ends `failed`, `cancelled` or `expired` is reported, not asked again.
- ✨ - `aidd-polite-http` Skill - Plans and reviews how fab-test's code treats the services it calls: a class for every failure, `Retry-After` as a floor, one retry layer, and one sentence for the caller. The AIDD router loads it whenever a task plans, changes or reviews code that makes an HTTP request. Its audit of fab-test's seven HTTP call sites is in `references/known-gaps.md`, filed as two plan.md tasks.

## 2026-11-21

- ✨ - `fab-test data-agent` - Regression-tests deployed Fabric Data Agents by asking them real questions with promptfoo (pinned `0.124.0`, installed on first use; Node 22+). A suite, `fab-tests/data-agent/<Item>.DataAgent.promptfoo.yaml`, pairs with its `*.DataAgent` folder by `logicalId` and holds promptfoo-native assertions and multi-turn conversations. fab-test resolves the agent's URL from `--workspace` (or `FABRIC_WORKSPACE_ID`, or `workspace:` in config) and the item's name. Every run is a service run, with a service principal only, and it's never part of `local`. `all` includes it only when a workspace is set. Over 5 agents in a workspace stops unless `--all`. Results use the one envelope, exit codes, `-q`/`-v`/`--format json`, the HTML report and telemetry (`fabric_dynamic_analysis`, `artifact_type: DataAgent`, answers redacted but kept). A run shows each answer as it lands, then ✓/✗ per test. Alias `agent`. Enabled by default. `FAB_TEST_ENABLE_DATA_AGENT=0` turns it off.
- ✨ - `fab-test data-agent tests init` And `tests lint` - `init` asks for your questions, an expected answer for each (Enter means the agent should decline), how it matches with one key (`n`umber accepts `16,376` or `16376`, `c`ontains, e`x`act, `s`tarts with, `e`nds with, `p`attern, `r`efuses), and follow-ups in the same conversation. `?` lists suggestions from the agent's tables and measures. It never writes a guessed answer. An existing suite is listed first, with `[a]dd (Enter) | [r]eplace all`. A question it already has asks keep or replace. `--answers FILE` and `--questions` give an agent or a pipeline the same choices. `lint` checks pairing, test ids and credentials offline, then runs `promptfoo validate` on the config the run would use. Exit 0, 1, 2, or 127 without promptfoo.
- 🔒 - Data Agent Suites Can't Steer The Token - The bearer token goes only to `https` Fabric and Power BI hosts. Redirects are refused, and server ids are quoted into paths. Another host needs `FAB_TEST_DATA_AGENT_ALLOWED_HOSTS` in the caller's environment, never in the suite. A suite's own `base_url`/`fabric_urls` on another host is a lint finding and a refusal before promptfoo starts. On a Fabric host it's a lint warning. promptfoo's environment carries no service-principal secret: the provider reads it from a private temp file, deleted after the run. A suite may not set `FAB_TEST_*`, `FABRIC_*`, `AZURE_*` or `PROMPTFOO_*` in `env:`. A suite is still code: run it only from trusted branches.
- 🐛 - Data Agent Runs Fail Fast And Say Why - Fabric's `"isRetriable": false` is final. A paused capacity says to resume it. A poll timeout is final, so one test no longer waits 4× `--timeout`. A conversation turn is never posted twice by a retry, and a thread whose post failed is still deleted. The summary of an error envelope now reads `error: <why>`, not `no findings`, for every analyzer.
- ✨ - Test Files Live In `fab-tests/` - Slicer contracts and Data Agent suites were written beside each item, among dozens of Fabric folders, where a person couldn't find them. `contract init` and `tests init` now write to `fab-tests/pbir/` and `fab-tests/data-agent/` at the root of the repository holding the items. That's outside the Fabric Git-connected folder, so Commit to Git can't delete them, and a Git subfolder never becomes a workspace folder. Every run and verb reads `fab-tests/` as well as `--artifact-dir`, and files still pair by `logicalId`, so a contract or suite beside its item keeps working, and `init` extends it where it is. `--tests-dir`, `FAB_TEST_TESTS_DIR` or `tests_dir:` in `fab-test.yml` moves the folder. Outside any repository, `init` writes beside the item as before. **Behavior change**: a new contract from `contract init` is written to `fab-tests/pbir/`, not beside the report.
- 🐛 - `fab-test pbir lint` No Longer Passes Having Checked Nothing - It ran a TARGET named `lint`, found no report and exited 0. It now exits 2 with `did you mean: fab-test pbir contract lint`, carrying the TARGET and flags as typed; `pbir init Sales` and `pbir contracts init` say the same instead of argparse's "unrecognized arguments". **Behavior change** for a script that ran `fab-test pbir lint` and relied on its 0. An item really named `init`, `lint` or `contracts` still runs as a TARGET.
