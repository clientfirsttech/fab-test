## Standalone Tasks

A missing prerequisite reads as a rendering verdict, which breaks "tell the caller how to fix it". Detect the missing plugins before the run (or recognise a pytest usage error) and exit `127` naming `pip install "cft-fab-test[dev]"`, as the other analyzers do for a missing tool; `doctor` should report playwright not ready for the same reason.
- **`--format json` on `local` and `all` is not one document** — found 2026-09-29 while verifying Terse CLI Output; identical on `origin/main`, so not a regression. Each analyzer's `_print_summary` prints its own `{"analyzer": ..., "artifacts": [...]}` document, then `all`/`local` print their aggregate after it, so stdout is several concatenated documents and `json.load` fails with "Extra data". The fab-test skill promises exactly one. `emit_own_json` in `_run_analyzer` already knows to skip the per-analyzer document for `all` and `local`; `_print_summary` just isn't given it. Decide the shape first (aggregate only, as the skill says) and pin it with a test that parses `local --format json` and `all --format json` whole.
- **Unguarded `::notice::` in `invoke_playwright.py`** — three `log("::notice::...")` calls (lines 749, 792, 967) print the GitHub Actions prefix on a laptop, the same defect Terse CLI Output fixed for tool-bootstrap notes. Not changed there because playwright could not be run for real without a service principal; route them through the same CI check and verify against a live workspace.
- **Analyzer result line is still restated by the CI annotation** — outside CI the parent replays each analyzer's stderr annotation, so `PBIR Inspector found 11 finding(s) (errors: 11, warnings: 0, exit code 0)` follows the wrapper's own `📊 11 finding(s) ...` and precedes the summary row. Skipping a replayed line equal to the envelope's `message` is fragile as things stand (the BPA annotation appends `, exit code N`); the wrappers and the replay need to agree on one message first.

Then work down [known-gaps.md](.github/skills/aidd-analyzer-contract/references/known-gaps.md); first, confirm through the CLI that `fab-test a11y --fail-on warn` doesn't fail on warning-only findings, as the code suggests.
