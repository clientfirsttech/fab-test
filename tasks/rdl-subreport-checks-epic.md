# RDL Subreport Checks Epic

**Status**: 📋 PLANNED — awaiting approval of the decisions below.
**Goal**: `fab-test rdl` flags a subreport whose parameters don't match its child (SUB-03) and, against a workspace, one whose name doesn't resolve to exactly one report (SUB-04).

## Overview

Both failures appear only when a reader opens the report: the service accepts the upload either way. Microsoft documents each one ([Troubleshoot subreports](https://learn.microsoft.com/en-us/power-bi/paginated-reports/subreports-troubleshoot), [Subreports in Power BI](https://learn.microsoft.com/en-us/power-bi/paginated-reports/subreports)): "One or more parameters were not specified for the subreport" when the parent doesn't set the child's mandatory parameters; "could not be found at the specified location" when no report of that name is in the same workspace (names are case-insensitive); and silently wrong content, because a workspace allows two reports with the same name. The engine checks one `.rdl` at a time, so SUB-03 needs the wrapper to find the child and pass its parameters in; SUB-04 needs the workspace's item list, so it runs only in service mode.

Decisions to approve:

1. **Finding the child locally** (SUB-03): `Subreport/ReportName` (its last path segment) matched case-insensitively, as the service matches it, to `NAME.rdl` or `NAME.PaginatedReport/NAME.rdl` under the run's artifact root. No match, or more than one, gives no SUB-03 finding.
2. **Which child parameters are mandatory** (SUB-03): those with no `DefaultValue`. Whether `Nullable` or `AllowBlank` alone makes one optional is settled by the render check below, not assumed.
3. **A passed parameter the child doesn't declare** (SUB-03): Microsoft says the two sets should match but names an error only for a missing one. It is part of SUB-03 only if the render check shows it fails; otherwise it's dropped.
4. **SUB-04 scope**: service mode only (`rdl --workspace`, `all --workspace`), counting `PaginatedReport` items in the workspace whose name matches case-insensitively: 0 is an error (not found), 2 or more is an error (ambiguous). Apps and shared reports are out of scope.

## Subreport render check

Before writing either check, deploy a parent and a child to fab-test [Dev] and render through the export API, as PRM-07's severity was settled.

**Requirements**:
- Given a parent that omits a child parameter with no default, should confirm the "not specified" error
- Given an omitted parameter that is only `Nullable`, or only a String with `AllowBlank`, should record whether it renders, which settles decision 2
- Given a parent that passes a parameter the child doesn't declare, should record whether it renders, which settles decision 3
- Given 50 Subreport items that all name one child, should record whether it renders: SUB-02 counts elements, Microsoft says "50 unique subreports", so SUB-02 may be a false positive for repeated use of one child

## SUB-03 check

Catalog rule SUB-03, "Subreport parameters match the child report", severity error, Tier C, with a cross-file pass in `invoke_rdl_lint.py`.

**Requirements**:
- Given a mandatory child parameter the subreport doesn't pass, should fire once per (subreport, parameter), naming both reports
- Given a child that can't be found, or matches more than one file, should pass without a finding
- Given the render check's results, should apply decisions 2 and 3 as settled there

---

## SUB-04 check

Catalog rule SUB-04, "Subreport resolves to one report in the workspace", severity error, Tier C; service mode only, from the item list the export already fetches.

**Requirements**:
- Given no `PaginatedReport` in the workspace matching the name case-insensitively, should fire, naming the closest names
- Given two or more matches, should fire, naming each match's ID
- Given a local run, should report SUB-04 as `skip` with the reason that it needs `--workspace`
