# RDL Subreport Parameters Epic

**Status**: 📋 PLANNED — awaiting approval of the two decisions below.
**Goal**: `fab-test rdl` flags a subreport whose passed parameters don't match its child report (SUB-03).

## Overview

A subreport that passes a parameter the child doesn't declare, or omits one the child requires, fails at render time with "One or more parameters were not specified for the subreport" — never at upload, so nothing catches it before a reader does. The child usually sits in the same repository, but the engine checks one `.rdl` at a time, so SUB-03 needs the wrapper to find the child and pass its parameters in.

Decisions to approve:

1. **Finding the child**: `Subreport/ReportName` (its last path segment) is matched by name to `NAME.rdl` or `NAME.PaginatedReport/NAME.rdl` under the run's artifact root. No match, or more than one, gives no SUB-03 finding: whether the name resolves is SUB-04's question (service mode, not in this epic).
2. **A required child parameter** has no `DefaultValue`, is not `Nullable`, and (for a String) is not `AllowBlank`.

---

## SUB-03 check

Catalog rule SUB-03, "Subreport parameters match the child report", severity error, Tier C, with a cross-file pass in `invoke_rdl_lint.py`.

**Requirements**:
- Given a passed `Subreport/Parameters/Parameter/@Name` the child doesn't declare, should fire once per (subreport, parameter), naming both reports
- Given a required child parameter the subreport doesn't pass, should fire once per (subreport, parameter)
- Given a child that can't be found, or matches more than one file, should pass without a finding
- Given a child parameter with a default, `Nullable`, or a String with `AllowBlank`, should not require it
- Given parameter names that differ only in case, should treat them as different (RDL names are case-sensitive)

---

## SUB-03 fixtures

`SUB-03` passes one parameter its child doesn't declare and omits one it requires; `SUB-03-Pass` passes exactly the child's required parameters. Both are generated by `tools/generate_rdl_fixtures.py`, with the child as a third generated fixture.

**Requirements**:
- Given each fixture, should be accepted by fab-test [Dev] and saved from `getDefinition`; a rejection keeps SUB-03 planned with the reason recorded here
- Given `SUB-03.rdl`, should trip only SUB-03; given `SUB-03-Pass.rdl` and the child, should trip no rule
